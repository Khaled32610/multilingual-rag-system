# Phase 10 — Grounded Generation

## Scope

Phase 10 connects an existing retriever to the configured local LLM client. It retrieves evidence, builds the prompt with that evidence, generates an answer, and returns the retrieved chunks with the answer so citation and faithfulness checks can use the original evidence in Phase 11.

## Decisions

- Retrieval and LLM implementations are injected into `GroundedGenerator`. The generation layer does not silently choose a retrieval strategy. The selected default LLM is `gemma3:4b` (see `docs/benchmarks/llm_benchmark_results.md`), while callers can inject another model for comparisons.
- The prompt instructs the model to use only the retrieved excerpts, abstain when the answer is absent, cite excerpt numbers, match the query language, and ignore instructions embedded in excerpt text.
- Empty retrieval results are passed to the prompt so the model can return the configured abstention response.
- `GeneratedAnswer` retains answer text, exact retrieved chunks, model name, latency, and token counts.
- Citation correctness and evidence faithfulness remain Phase 11 responsibilities; citations generated by the model are not certified here.

## Entry point

Use `GroundedGenerator(retriever, llm, top_k=5)` and call `generate(query)`. `retriever` must expose `retrieve(query, top_k=...)`; `llm` must implement `BaseLLM` (for example, `OllamaLLMClient`). Temperature and maximum output tokens default to `configs/config.yaml` settings.
